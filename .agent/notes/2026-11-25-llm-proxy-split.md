The host keeps the service: `modules/llm/proxy.nix` generates `/etc/llm-proxy/config.json`, runs
`${pkgs.neg.llm-proxy}/bin/llm-proxy` on `127.0.0.1:9300` and owns the `llm-proxy` unit. `llmctl`
stays in the tree on purpose — it is this host's fleet controller (it inspects systemd units, reads
the `/etc/nixos` git diff for `llmctl commit`, and carries the model catalog with local
measurements), not a portable tool.

## Decisions taken with the move

- **`main.py` became `llm_proxy.py`.** A repository main file should be named after the project; the
  suite loads it by path, so the only extra change is the `HERE / "llm_proxy.py"` line in the test
  and the `install` line in the package.
- **Two checks, one suite.** `package.nix` keeps `doCheck = true` with `unittest discover`, so
  building the package runs the suite; `checks.unit` in the flake runs the same discovery straight
  from the checkout, which catches a file the packaging happens to hide (a missing `src` entry, a
  discovery pattern that stops matching).
- **The flake pins the host's nixpkgs** and CI runs the suite twice: once with a plain
  `python -m unittest` (fast feedback, no Nix), once through `nix flake check` and `nix build`.
- **No config file in the repository.** The config is generated by the host module and can carry
  per-model settings; the repo documents the schema in the README instead.

## How the host consumes it

- `flake.nix`: `llm-proxy.url = "github:neg-serg/llm-proxy"`, `inputs.nixpkgs.follows = "nixpkgs"`.
- `packages/overlay.nix`: `llm-proxy = final.callPackage (inputs.llm-proxy + "/package.nix") { };` —

## Gaps to fix later

1. **`llmctl` stays here.** If it is ever extracted, it needs its own tests first: today it has
   none, and its host coupling (units, `/etc/nixos`, the measured catalog) is the reason it is not a
   portable tool.
1. **The suite has no live server.** The guards are exercised with fakes, not against a running
   `llama-swap`; the swap-race retry in particular is only unit-tested at the decision level.
1. **The version is a literal** (`0.1.0`) because a Python app carries no manifest; a release would
   need a version source the package reads.
