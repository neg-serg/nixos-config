# hy3 detach "still broken": the plugin is not in the running session

Asked on 2026-10-24 why hy3 detach is still broken. Detach itself is not the fault: hy3 is not
loaded in the compositor that is running, so every hy3 bind (detach included) is a silent no-op.
Recorded here because the session was left as is (no relogin, no unit added).

## Symptom

`ALT+E -> e` (special submap) and `d` (tiling submap) do nothing. No notification, no log line, no
crash: `hy3detach()` in `files/gui/hypr/hyprland.lua:313` starts with
`if not (plugin and plugin.detach) then return end`, so a missing plugin is indistinguishable from a
broken dispatcher.

## Evidence from the live session (2026-10-24 16:2x MSK)

- `pgrep -a Hyprland` — PID 349980, started Fri Oct 23 14:03:05, args `--watchdog-fd 4 --safe-mode`.
- `hyprctl plugin list` — hyprglass, HyprCapture, dynamic-cursors, hyprliquid; no hy3.
- `hyprctl getoption plugin:hy3:tabs:height` — `no such option`, i.e. the namespace is not
  registered.
- `hyprctl getoption general:layout` — `str: hy3`: the user config was applied, the algorithm is not
  there.
- `$XDG_RUNTIME_DIR/hy3-setup.log` — last entry `2026-10-23 13:13:35`, `ok`: the helper did not run
  in this session.

The instance's own `hyprland.log` confirms it booted on the recovery config:
`WARN ]: No config file found; attempting to generate.`, and `recoverycfg.lua` next to it is the
stock autogenerated config (dwindle). So the `general:layout = hy3` seen over IPC arrived later,
through a config reload, not through a start.

## Mechanism

1. On 2026-10-23 14:02 the previous (normal) session died: `amdgpu ... ring gfx_0.0.0 timeout` in
   the journal, then `SIGABRT` inside `CGLFramebuffer::internalAlloc <- blurFramebufferWithDamage`
   (crash report 4977). That stack has no hy3 frame; hy3 was in the plugin list of that report.
1. The compositor came back with `--safe-mode`. In safe mode `Jeremy::getMainConfigPath()` returns
   `<instance>/recoverycfg.lua` (`src/config/supplementary/jeremy/Jeremy.cpp:23-26`).
1. Choosing "Load config" in the safe-mode dialog runs `m_safeMode = false; Config::mgr()->reload()`
   (`src/Compositor.cpp:929`): a **reload**, not a start.
1. `hy3-setup` is invoked only from the `hyprland.start` hook
   (`modules/user/nix-maid/hyprland/main.nix:961`), and that hook is wired to `m_events.start`
   (`src/config/lua/LuaEventHandler.cpp:165`), which the compositor emits once at startup. A reload
   after leaving safe mode therefore never loads hy3, while every workspace already carries the user
   config (`layout = hy3`, whose algorithm is missing, so those workspaces run on the fallback
   algorithm).
1. The other four plugins are back because they have systemd user units on
   `hyprland-session.target`; hy3 has no unit — the start hook is its only load path.

## What is not the cause

- The patch: the deployed plugin `/nix/store/6lbc1ccxzwa8qiyap2ggpcvzai61fm8b-hy3-0.56.0.1` is built
  from exactly the current `modules/user/nix-maid/hyprland/hy3-detach-float.patch` (sha256
  `95e69bc0d94c03f1fd095ef1b1e4b1ebd98fc76750d6e15c509afbac9267e528`, identical to the snapshot in
  `/nix/store/79mplv7z3a1h5w0wc0v731dssb4rqd8b-hy3-detach-float.patch`).
- The old detach crash: report 122669 (2026-10-23 11:26, `SIGSEGV` in
  `Hy3Layout::detachedNodeAlive <- findDeadDetachedNode <- pruneDetachedNodes`) ran the previous
  build `8dhjc47g`, i.e. before `95f537c3` moved the pruning out of the `window.destroy` /
  `window.moveToWorkspace` listeners. That fix is deployed.
- Rendering: crash 4977 and the 2026-10-23 12:34 / 14:03 aborts have no hy3 frames.

## Not verified

The detach toggle itself was not exercised after the fix: the only session that had the fixed hy3
loaded (2026-10-23 13:13-14:02) ended in the renderer abort, and no later session loaded hy3 at all.
A nested Hyprland cannot stand in for a live check in the agent sandbox: it exits with
`CBackend::create() failed!` because `/dev/dri/*` is not accessible there (`EACCES` on
`renderD128`).

## Options when this is picked up

1. Relogin — cleanest: a normal start runs the hook and `hy3-setup` loads the patched `.so` (also
   picks up the current system generation, which the 2026-10-23 session predates).
1. `hy3-setup` in the live session — idempotent, loads the plugin and re-tiles the workspaces; the
   open windows move and a failed load takes the compositor down with the clients.
1. Durable: give hy3 a systemd user unit alongside `hyprcapture.service` /
   `hyprdynamiccursors.service` (`modules/user/nix-maid/hyprland/main.nix`), so a recovery session
   gets the layout back without a relogin, and make `hy3detach()` report the missing plugin instead
   of returning silently.
