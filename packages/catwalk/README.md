# catwalk

A miniature platformer drawn on the user's 32:9 waterfall wallpaper. The painting is not a backdrop:
it *is* the terrain. One world unit is one wallpaper pixel, the background is copied 1:1 with
nearest sampling, and a ginger cat runs, curls and swims through it.

On top of the painted rocks sits a procedural layer: every 1920x1080 screen gets a scenario composed
live by a two-role **director** — a generator proposes encounters, a critic scores them for
surprise, build diversity, situation variety and fairness, and the best one is instantiated. A
hovering badnik is the run's opponent; rings and monitor capsules feed the build.

## Running

```
nix run /etc/nixos#catwalk
```

Or, with the package installed, plain `catwalk`.

| Key                    | Action                                  |
| ---------------------- | --------------------------------------- |
| `A` / `D`, `←` / `→`   | run                                     |
| `Space`, `W`, `↑`, `Z` | jump; in water: leap out                |
| `S`, `↓`               | dive (in water)                         |
| `R`                    | restart (on the win/lose screen)        |
| `F11`                  | toggle fullscreen                       |
| `F12`                  | save a screenshot to `/tmp/catwalk.ppm` |
| `Esc`                  | quit                                    |

The on-screen text is Russian because the game is for this machine's owner; code, comments and this
document stay English.

## The procedural layer

The scenery is fixed, so all novelty lives in the dynamic layer. Content is generated **per screen
chunk** (`floor(player.x / 1920)`, one viewport wide): nothing is placed outside the screen you are
on.

- **Generator** draws 8 candidate encounters from a seeded RNG: 1-3 badniks (patrol, chase, shoot
  behaviour), a ring arc over a platform (or over the lake when the chunk has no ground), and one
  monitor capsule whose upgrade is biased toward the type the run has offered least.
- **Critic** scores each candidate:
  - `surprise` — 1 minus the cosine similarity to the last eight screens;
  - `build` — entropy of the upgrades offered so far;
  - `situation` — distinct badnik behaviours plus vertical spread;
  - `fairness` — no spawn in water/off-screen, no opponent dropped on the cat's head, rings above
    the waterline;
  - `fun = 0.30*surprise + 0.24*build + 0.26*situation + 0.20*fairness`.
- The best candidate is used and the others stay in the log. The HUD shows the chosen screen's fun
  score and novelty; `--metrics PATH` writes the whole run (every chunk's scores, rings, stomps,
  hits and taken upgrades) as JSON.
- `--seed N` fixes the whole run; the seed is printed at startup.

The scenario name (chaos, ambush, chase, …) is derived from the mix the critic picked, so the toast
also reports what kind of screen you walked into.

## The opponent

A badnik hovers in every generated screen. Behaviour is part of the proposal:

- `Drifter` patrols a platform,
- `Chaser` closes in when the cat is within 700 px,
- `Shooter` fires slow energy bolts every 1.9 s.

Curling in the air and landing on one destroys it (a stomp); touching one, or a bolt, costs a heart
and knocks the cat away. Three hearts end the run and show the report. A shield absorbs one hit.
Monitor capsules grant a build: speed, jump, magnet or shield.

## How the painting becomes the level

- `assets/world.jpg` is the wallpaper at full resolution (7680x2160). The game window is 1920x1080
  world pixels scaled 2x, which is exactly the 3840x2160 panel; a standing-still frame shows the
  wallpaper crop without resampling.
- `assets/cat.png` is a 9-frame sheet (idle 0..1, run 2..5, curl-ball 6..8) generated by
  `tools/generate_cat.py`; `assets/badnik.png` (hover A/B, destroyed) by `tools/generate_badnik.py`.
- The painting's own crab sat exactly on the spawn ledge. `tools/make_world_patch.py` clones a clean
  piece of the same ledge and `src/assets.rs` composites it over the world at load time, so the cat
  is the only character there. The source JPEG stays untouched; everything outside that 120x106
  patch is bit-identical.
- Platforms sit on the rock edges that are actually visible in the picture: the plateau at the grass
  fringe (`y = 1840`) and the boulder staircase at `1836 / 1900 / 1984` (`tools/measure_level.py`).
  The lake surface follows the painted shoreline through `Level::waterline`.
- The waterfall streaks and lake highlights are generated at startup from the pixels: only bright
  bluish pixels inside the falls become moving streaks, only blue pixels in the lake become shimmer.

## Fun study

`--study N` runs N simulated campaigns (four screens each) through the exact director in parallel
and reports what the fun metric actually rewards:

```
catwalk --study 2000000 --study-json /tmp/study.json
```

2M campaigns take about 3.5 s on this machine (32 threads, ~555k runs/s). Findings from that run:

- the score is dominated by `situation` (r = +0.96 against fun); `surprise` is anti-correlated at
  campaign level (r = -0.43) because the first screen always scores 1.0 and later screens cannot
  recover it;
- `build` saturates at ln(4) after four capsules and `fairness` is a constant 1.0, so neither
  discriminates runs;
- novelty decays 1.00 -> 0.11 -> 0.08 across the route, which is the real limit of a four-screen
  campaign;
- a sweep over 12 random weightings found the most varied campaigns at
  `build 0.35 + situation 0.34 + surprise 0.15 + fairness 0.16` (variety 4.60 against the default
  4.19);
- pure scenarios (patrol/chase/shoot) are rare unless the generator proposes them deliberately, so
  half of its proposals now use one shared behaviour.

This measures a proxy: surprise, build entropy and situation variety are properties of generated
screens, not a human rating.

## Verification

Unit tests (no display needed):

```
cargo test
```

Headless QA frame with the director already run:

```
SDL_VIDEODRIVER=dummy cargo run -- --shot /tmp/frame.ppm --state play \
  --pos 1300,1984 --cam 250,1020 --warmup 1.2 --metrics /tmp/run.json
```

`--debug` draws platform boxes and the player's hitbox. The background-only comparison against the
wallpaper crop is `--clean` plus an ImageMagick `compare`: the remaining difference is JPEG-decoder
rounding (max 4/255 per channel).
