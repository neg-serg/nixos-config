# player-proto: font audit + dark theme proposal

Scope: `prototypes/player-proto` (Rust, winit + ash + cosmic-text 0.14.2 + swash 0.2.10,
single-channel R8 glyph atlas). Target: a deterministic font stack and a dark UI palette for a
1440x900 window with three panes and a now-playing panel.

Everything below was measured on this host (NixOS 26.11, Hyprland/Wayland, RX 9070 XT). No file
outside this directory was modified, nothing was installed, nothing was built.

Note on language: this document is deliberately ASCII-only (no Cyrillic, no CJK) because the repo
lint `scripts/dev/check-markdown-language.sh` rejects both in `*.md`. The Russian UI strings are
therefore referenced by code line and described, never quoted literally.

## 0. How to reproduce the checks

```sh
fc-match sans-serif                                  # what cosmic-text gets for Family::SansSerif
fc-list | wc -l                                      # faces fontconfig exposes
fc-list --format '%{file}\t%{index}\t%{family[0]}\t%{style[0]}\t%{weight}\n' '<Family>'
fc-list ':charset=0430' --format '%{file}\n' | sort -u # who has Cyrillic small a
fc-query --format '%{family}\n%{style}\n%{weight}\n' <file>
python3 - <<'PY'   # fontTools 4.63.0, present on this host
from fontTools.ttLib import TTFont, TTCollection
f = TTCollection(PATH, lazy=True).fonts[0]           # or TTFont(PATH)
cm = f.getBestCmap(); [hex(c) for c in range(0x400,0x500) if c not in cm]
PY
```

Contrast ratios are computed, not guessed. Formula (WCAG 2.1, 7.1.4 style):

```
C = (L_lighter + 0.05) / (L_darker + 0.05)
L = 0.2126*R + 0.7152*G + 0.0722*B            (linear-light, per channel:)
l(c8) = c8/255;  l <= 0.04045 -> l/12.92 ; else ((l+0.055)/1.055)^2.4
```

All sRGB values used are the hex codes given in the tables; they are the exact RGB8 values that the
proposed `[f32;4]` constants produce (`round(v*255)`), so the ratio for a token and the ratio for
its float triple are identical.

## 1. What the app actually renders today (root cause)

`Fonts::new()` calls `FontSystem::new()` (`src/text.rs:38`). cosmic-text 0.14.2 depends on fontdb
0.16.2 with `fontconfig-parser` (verified in `Cargo.lock`), so generic families are resolved through
fontconfig. On this host fontconfig is configured like this:

```
/etc/fonts/conf.d/52-nixos-default-fonts.conf   ->  generated by modules/fonts/default.nix
  alias binding="same" sans-serif -> Iosevka
  alias binding="same" serif      -> Iosevka
  alias binding="same" monospace  -> Iosevka
```

```console
$ fc-match sans-serif
Iosevka-Regular.ttf: "Iosevka" "Regular"
$ fc-match "sans-serif:charset=0430 044F 0451"
/nix/store/r471yk6n1rgmm1xsylx3n5zsq4n2q2c4-iosevka-nerd-font-34.7.0/share/fonts/truetype/Iosevka-Regular.ttf Iosevka Regular
```

Consequences, all measurable:

1. **Every string in the UI is currently Iosevka**, a monospaced face with a 0.5 em advance
   (verified: digit advances are all exactly `0.500` em). That is why the "inconsistent" look is
   actually a uniform but wrong look: proportional labels, titles and Russian text are all set in a
   terminal face narrower than any UI sans.
1. **Two different builds claim the family name `Iosevka`**: 24 faces across
   `~/.local/share/fonts/iosevka-neg/` (fontversion 2230845) and
   `/nix/store/r471yk6n1rgmm1xsylx3n5zsq4n2q2c4-iosevka-nerd-font-34.7.0/` (fontversion 2274099).
   Different bytes (sha256 `5e087cb0...` vs `d3699da4...`), same family name -> face selection by
   name is a coin flip. Never select "Iosevka" by name in the app.
1. **Fontconfig exposes 1438 faces / 285 family names**, and `FontSystem::new()` walks all of them
   at startup.
1. Symbol lookups are equally indirect: `fc-match "sans-serif:charset=25B6"` also answers Iosevka,
   so the transport glyphs happen to exist today but are not guaranteed by anything the app
   declares.

The proposal below removes fontconfig from the critical path: the app pins families **by file** and
asks for them by name.

## 3. Recommendation

Three families, one role each. Rationale in one line: **Inter** and **JetBrains Mono** have almost
identical vertical metrics (x-height 0.546 vs 0.550 em, cap height 0.728 vs 0.730 em, measured from
the font files), so a 12 px number and a 12 px label sit on the same optical baseline; **DejaVu
Sans** is the only family on this host that covers every UI glyph the code currently draws.

Do **not** load `InterVariable.ttf` first: it is one file with `wght 100-900`, which is nicer, but

screenshotting the same string at weight 400 and 600; if the stems match, the axis is being
ignored.)

### 3.2 Family names to pass to `Attrs`

Verified from name ID 1 of each file:

- `Inter` - verified per face in `Inter.ttc`: face 0 and face 14 carry name ID 1 = `Inter`, while
  the 500/600/800 faces carry name ID 1 = `Inter Medium` / `Inter SemiBold` / `Inter ExtraBold`
  **and name ID 16 (typographic family) = `Inter`**. fontdb collects name IDs 1 and 16, so
  `Family::Name("Inter")` matches all of them and `usWeightClass` (400/500/600/700) picks the face.
  Do not select by the name-ID-1 strings; they are not stable across the collection.
- `JetBrainsMono NF` (name ID 1; name ID 16 is `JetBrainsMono Nerd Font`, both resolve).
- `DejaVu Sans`.

### 3.3 Fallback order

**Cyrillic (UI text):** Inter already covers 248/256 of U+0400-U+04FF and 66/66 of the Russian
alphabet, so in practice there is no fallback step for Russian. When a codepoint is missing, the
chain should be:

```
Inter  ->  Noto Sans        (256/256 of U+0400-U+04FF, the only complete text face here)
       ->  DejaVu Sans      (256/256, also has the symbols)
       ->  Unifont          (last resort, ugly but complete)
```

Do not put `TeX Gyre Heros` or `Outfit` anywhere in the chain: both are 0/66 for Russian.

**Numerals:** JetBrainsMono NF covers 122/256 of U+0400-U+04FF (Russian alphabet complete, extended
Cyrillic not). Numbers are ASCII, so this only matters if a numeric string is ever localised - keep
numerals pure ASCII (`12:34`, `320 kbps`, `07`).

**Symbols (`U+25B8 U+258F U+25A0 U+25B6 U+25C0 U+25AE U+266A`):**

```
DejaVu Sans   (covers all seven)
  -> Iosevka  (covers all of them plus the media block)
  -> Noto Sans Symbols 2 (partial)
```

Two rules that come out of the numbers:

1. **Never route these glyphs through Noto Sans** - it is a text face with 0/22 symbol coverage, so
   a lookup that lands there silently produces a blank box.
1. **Prefer drawing the transport controls as shapes.** `◀◀ / ▮▮ / ▶▶` are the only reason the UI
   needs a third font. The renderer already has an SDF rounded-rect pipeline and a triangle can be
   three vertices: replacing those 3 strings with 2 triangles + 2 rounded rects + 2 triangles
   removes the symbol fallback and fixes the optical inconsistency between a 15 px text glyph and a
   20 px text glyph seen today at `src/bin/player.rs:991`.

### 3.4 System-level note (proposal only, not applied)

`modules/fonts/default.nix` sets
`fonts.fontconfig.defaultFonts = { serif, sansSerif, monospace } = [ "Iosevka" ]`, which is what
makes `fc-match sans-serif` return a monospace face for every non-declaring app on the host
(Hyprlock, GTK, this prototype). If you want the *whole session* to stop doing that,
`sansSerif = [ "Inter" ]` is the minimal change and keeps `monospace = [ "Iosevka" ]` for terminals.
That is a system change with a visual blast radius; the app-level fix above is independent of it and
should land first.

## 5. Typography scale

Anchor and ratio: a **1.125 (major second)** series anchored at 16 px, rounded to whole pixels, with
a hard floor of 11 px. Derivation:

```
16 * 1.125^-3 = 11.24 -> 11   (caption floor)
16 * 1.125^-2 = 12.64 -> 12   (secondary)
16 * 1.125^-1 = 14.22 -> 14   (body)
16 * 1.125^ 0 = 16            (emphasis)
16 * 1.125^ 1 = 18            (section / title step 2)
16 * 1.125^ 2 = 20.25 -> 20   (title)
16 * 1.5      = 24            (display, a perfect fifth above the anchor)
```

Why these anchors and not a pure geometric ladder: at 1x with grayscale antialiasing (no hinting
path in swash here), Inter's x-height is 0.546 em, i.e. **6.0 px at 11 px, 6.6 px at 12, 7.6 px at
14, 8.7 px at 16**. Below 11 px the x-height drops under 6 px and Cyrillic lowercase (which carries
the same x-height but denser side bearings) turns to mush - that is the floor. Above 16 px a 1.125
step is already a 14% jump, so 18 and 20 are enough for a two-step title hierarchy; 24 is reserved
for the album-art placeholder and future hero text.

- Hover must not fight the play button, the one filled accent shape in the panel. It cannot take a
  wash, so it takes a 2 px `accent_soft` ring instead: a weight cue, no new colour.

## 8. What not to do with a single-channel glyph atlas

The atlas is 2048x1024 `R8_UNORM` (`src/scene.rs:4-5`, `src/gpu.rs:603`), filled by swash, and
`src/text.rs:115` accepts **only** `SwashContent::Mask`. Consequences:

1. **No subpixel (LCD/ClearType) antialiasing.** Three-channel coverage needs an RGB atlas and a
   per-channel blend; with one channel and flat-vertex colours there is nothing to bleed. Grayscale
   AA is the only option - do not try to fake it by offsetting the colour per glyph.
1. **No colour emoji - they are silently dropped, not just ugly.** Noto Color Emoji ships CBDT/CBLC
   bitmap strikes (verified: its table list is
   `CBDT CBLC GSUB OS/2 cmap head hhea hmtx maxp name post vhea vmtx`), which swash reports as
   `SwashContent::Color`; the `matches!` guard skips them and the glyph simply never appears. Keep
   emoji out of UI strings; if a decorative pictogram is needed, draw it with the SDF shape
   pipeline.
1. **Subpixel positioning multiplies atlas entries.** swash bins fractional glyph offsets into the
   cache key; a glyph rasterised at 4x4 subpixel bins costs 16 entries. With the number of distinct
   (size, weight) pairs capped by the type scale (7 sizes x 4 weights) and integer-origin text, the
   atlas holds thousands of glyphs comfortably; centring text with `x = (w - measure) * 0.5` at
   fractional offsets does not.
1. **The allocator never evicts.** `Atlas::insert` returns `None` when the shelves are full, and
   `text.rs` caches that `None` forever (`uv: None` in `glyph_cache`), so text stops appearing
   permanently. Cap the number of sizes, and on `None` either repack or grow the atlas - 4096x2048
   R8 is 8 MiB, which is noise on a 16 GB card.
1. **Blending happens in linear space into an `_SRGB` target.** `scene::linear()` converts the
   constants, so glyph coverage is multiplied in linear light - the classic result is text that
   looks 1 step thinner than the same font rendered by a 2D toolkit. Compensate with a weight step
   (400 -> 500) at 11-12 px, or apply an alpha ramp at upload (`a' = a^(1/1.2)`); do not just raise
   the text colour, that washes out the shape.
1. **No hinting, no pixel snapping.** swash/skrifa renders unhinted outlines; combined with the 11
   px floor from section 5, that is the whole legibility budget. Do not add a 10 px step.
1. **No per-glyph OpenType features.** cosmic-text 0.14.2 cannot enable `tnum`/`case`/`ss01`, so
   "just use tabular figures" is not available - the mono face is the answer (section 5), and
   uppercase headers must be uppercased in the string, not by a `case` feature.
