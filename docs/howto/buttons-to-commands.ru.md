## Цель

Постепенно убрать из dsh web GUI кнопки, которые дублируют текстовые команды (слэш-команды `/…` в
поле ввода, хоткеи, Enter и т.п.), чтобы интерфейс был управляем с клавиатуры, как терминал.

## Принцип

- **Кнопка → команда.** Для каждой кнопки сначала находим (или добавляем) текстовую команду/хоткей с
  той же функцией, затем прячем кнопку.
- **Прячем, а не удаляем.** Кнопки скрываются только CSS (DOM не трогаем) — изменение обратимо и не
  ломает React.
- **Если команды нет — добавляем её**, потом прячем кнопку.
- Место правок — личная скина **dsh-terminal-ui** (форк `dsh-web-ui`,
  `packages/dsh-terminal-ui/lib/client.js`), которая уже владеет внешним видом композера и инжектит
  один `<style>` на время жизни страницы.

## Механика (как вносить изменения)

1. Форк: `~/src/1st-level/@projects/dsh-web-ui` (workspace-link из `~/.dsh/profiles/web`, см.
   `pnpm-workspace.yaml`).
1. Правки — прямо в `packages/dsh-terminal-ui/lib/client.js` (у пакета нет `src/`, так уже делались
   прошлые коммиты `theme(terminal-ui): …`).
1. **Два слоя кода** (частая причина «не работает, хотя сделал»):
   - **клиент** (`lib/client.js`) сервер отдаёт **живьём** из форка (проверено:
     `/plugins/dsh-terminal-ui/client.js` == файл форка; rev-хэш пересчитывается на лету). Рестарт
     не нужен; страница теперь **перезагружается сама** (авто-вотчер rev, см. ниже).
   - **host** (`lib/index.js`: команды, роуты, инъекции сервисов) грузится один раз при старте dsh —
     после правок нужен `systemctl --user restart dsh`.
1. Проверка клиента:
   `curl -s http://127.0.0.1:3080/plugins/dsh-terminal-ui/client.js | grep <новый селектор>`.
   Проверка host: `node --check lib/index.js` + рестарт + проверка в палитре `/`.
1. Коммит в форк: `theme(terminal-ui): …` (как в истории).

### Авто-перезагрузка страницы при правках

В `client.js` есть вотчер: раз в 8 с читает свежую boot-страницу (`/`) и `location.reload()`-ит
вкладку, если изменился rev **любого** клиентского плагина — **или** сервис перезапускался (fetch
падал и снова поднялся). Поэтому правки скина применяются без F5, а после
`systemctl --user restart dsh` страница тоже перезагрузится сама (и в палитре появятся новые
host-команды, напр. `/export-md`). Разбор boot: regex по `window.__DSH_BOOT__ = {...}</script>`.

### Генерируемые конфиги (правило)

`~/.dsh/profiles/web/cordis.patch.yml` **генерируется** из
`modules/user/nix-maid/apps/dsh-market.nix` (активация при rebuild/логине; в файле шапка «Managed by
NixOS — do not edit»). Любые отключения/правки профиля вносить **в модуль**, иначе при
`nh os switch` правка затрётся. Это же касается отключения плагинов:
`- id: <plugin> / disabled: true` в модуле — и рестарт dsh.

## Шаг 1 (готово): кнопка «+» в поле ввода

**Что это.** Кнопка `+` в левой части поля ввода — это тумблер меню команд (тот же список, что
открывается при наборе `/`). Разметка из `@deepseek-ai/dsh-client-ui-conversation` (InputBar):

```jsx
<div className="…tools">
  <Tooltip label={t("input.commands")}>
    <button aria-haspopup="listbox" aria-expanded={commandMenuOpen}
            onClick={onToggleCommandMenu}>
      <IconPlusOutline16 size={14} />
    </button>
  </Tooltip>
  …
</div>
```

**Замена.** Функцию дублирует команда `/` в поле ввода — кнопка избыточна. Скрыта CSS-правилом в
`dsh-terminal-ui`:

```css
[data-composer-card] button[aria-haspopup="listbox"] {
  display: none;
}
```

Селектор стабилен: `data-composer-card` — постоянный data-атрибут карточки ввода;
`aria-haspopup="listbox"` в бандле конверсации встречается ровно один раз. Скролл-зона и клавиатура
не затронуты.

**Проверено.** После правки сервер сразу отдаёт обновлённый бандл (rev `09810766aafd` →
`a744c35a19fa`).

## Шаг 2 (готово): Отправить / Стоп

**Что это.** В правой части поля ввода — главная кнопка: «Отправить» (`aria-label="Send message"`),
а во время запуска — «Стоп» (`aria-label="Stop generating"`, отдельная кнопка при прерываемом
запуске субагента).

**Замена.**

- **Отправить** — уже дублируется **Enter** в поле ввода (Shift+Enter — новая строка, Ctrl+Enter —
  ускоренная отправка/«вставка» в очередь).
- **Стоп** — хоткея не было, добавлен **Esc** (JS-фича в `dsh-terminal-ui`): если запуск идёт
  (кнопка «Стоп» в DOM) и нет открытых попапов/модалок — кликаем по ней. Открытые меню Esc закрывает
  как раньше (React-обработчик срабатывает раньше, наш слушатель — в фазе всплытия).

CSS:

```css
[data-composer-card] button[aria-label="Send message"],
[data-composer-card] button[aria-label="Stop generating"] {
  display: none;
}
```

## Шаг 4 (готово): кнопки на сообщениях и в очереди

**Что это.** Ховер-панель действий сообщения (Копировать / Ветка) и кнопки очередных сообщений
(Изменить / Удалить / Вставка). Хоткеев не было.

**Выбор модели взаимодействия:** хоткеи действуют на **последнее** сообщение в ленте (решение
пользователя) — без трекинга мыши.

**Замена** (модификаторные комбинации — обычные буквы остаются для набора):

| Хоткей               | Действие                                                                      |
| -------------------- | ----------------------------------------------------------------------------- |
| `Ctrl+Alt+C`         | скопировать текст последнего сообщения (пользователя или ассистента)          |
| `Ctrl+Alt+B`         | ветка последнего сообщения (только ассистент, если доступно)                  |
| `Ctrl+Alt+E`         | редактировать последнее очередное сообщение (Enter — сохранить, Esc — отмена) |
| `Ctrl+Alt+Backspace` | удалить последнее очередное сообщение                                         |

Скрыто CSS (копировать/ветка — только внутри `[data-time-hover-root] [class$="_actions"]`, чтобы не
задеть кнопки копирования в блоках кода):

```css
[data-time-hover-root] [class$="_actions"] [aria-label="Copy"],
[data-time-hover-root] [class$="_actions"] [aria-label="Copied"],
[data-time-hover-root] [class$="_actions"] [aria-label="Branch into a new conversation"],
button[aria-label="Edit queued message"],
button[aria-label="Remove queued message"],
button[aria-label="Steer queued message"] {
  display: none;
}
```

Хоткеи диспатчат `.click()` по скрытым кнопкам — работают штатные обработчики приложения (clipboard,
fork, очередь).

## Шаг 5 (готово): сайдбар — новый чат и переключение сессий

**Что это.** Кнопки «New session» в сайдбаре (их две: бренд-слово и подписанная кнопка с иконкой —
обе вызывают `startSession`) и список сессий (`role="treeitem"` с `aria-selected`; строки папок
воркспейсов — с `aria-expanded`, поэтому не путаются). Хоткеев не было.

**Замена.**

| Хоткей                        | Действие                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `/new` (команда в поле ввода) | новый чат                                                                                                      |
| `Ctrl+Alt+N`                  | новый чат (быстрый хоткей)                                                                                     |
| `Ctrl+Alt+J`                  | следующая сессия в списке сайдбара                                                                             |
| `Ctrl+Alt+K`                  | предыдущая сессия                                                                                              |
| `Ctrl+Alt+W`                  | выбрать рабочую папку (когда поле ввода — триггер «Choose workspace»; Enter в фокусе тоже работает из коробки) |

**Команда `/new` — как это устроено.** Слэш-команды dsh выполняются на хосте
(`ctx.commands.register`), а «новый чат» — клиентское действие, поэтому хостовой команды мало.
Вместо этого скина регистрирует **клиентский источник команд** (сервис `inputTriggers`, тот же
конвейер, что у `/`): кандидат `new` попадает в меню при наборе `/`, `matchEnter` обрабатывает голый
`/new` + Enter, а `onPick`/`matchEnter` вызывают `ctx.workspaces.startSession()` (то же, что кнопка)
и снимают токен `/new` из поля через событие `slash/input-consume-token` (как это делает штатный
ui-commands). Заголовок отдельной группы меню скрыт CSS (`[data-source="local"]`), чтобы `/new`
читался как часть группы команд.

CSS:

```css
button[aria-label="New session"] {
  display: none;
}
[data-source="local"] {
  display: none;
}
```

## Шаг 6 (готово): переключение сессий командами + всегда в конец

**Команды переключения** (в том же клиентском источнике, что `/new`):

| Команда          | Действие                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `/session <имя>` | перейти к сессии: точное совпадение по названию → префикс → подстрока → фолбэк по содержимому сообщений (`sessions.search`) |
| `/next`          | следующая сессия в списке сайдбара                                                                                          |
| `/prev`          | предыдущая сессия                                                                                                           |
| `/new`           | новый чат (как раньше)                                                                                                      |

Механика: `onPick`/`matchEnter` источника вызывают `ctx.sessions.open(id)` / клик по строке списка;
токен снимается через `slash/input-consume-token`. Выбор `/session` из меню оставляет «/session» в
поле — дописываете имя и Enter.

**Всегда в конец.** Раньше чат восстанавливал сохранённую позицию скролла при открытии сессии
(оказывались на середине). Теперь скина подписана на `ctx.sessions.list` (store: `current` —
активная сессия): при любом изменении текущей сессии — клик в сайдбаре, `Ctrl+Alt+J/K`, `/session`,
`/next`, `/prev`, `/new` — скроллпорт `[data-conversation-scroll]` прыгает в конец (двойной rAF +
повтор через 700 мс, чтобы поймать догрузку). Дальше штатный обработчик видит «внизу» и продолжает
следовать за потоком.

## Шаг 7 (готово): правки кода/файлов разворачиваются

Карточки вызовов инструментов монтируются свёрнутыми (тело **не** в DOM, пока не открыто — CSS не
поможет, нужен клик по строке). Авто-разворот (тот же WeakSet-подход, что у Think/команд/контекста)
теперь покрывает и строки правок: варианты **`edit`**, **`write`**, **`code`** раскрываются сразу;
`read`/`search`/`bash` остаются свёрнутыми, чтобы содержимое файлов не затопляло колонку. Свёрнутая
вручную строка больше не разворачивается (только новые строки из новых ходов).

## Шаг 9 (готово): автокомплит имён сессий

  сообщением.
- `/session ` без аргумента показывает первые 8 сессий.

## Шаг 10 (готово): кнопки воркспейсов, телефон и обновление

**Кнопки воркспейсов в сайдбаре** (строки раздела Workspaces):

| Кнопка                              | Команда-замена                                                                                                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Строка воркспейса (раскрытие/выбор) | `/workspace <имя>` — переключение: точное имя → путь → префикс → подстрока; открывает последнюю реальную сессию воркспейса, пустого — заводит чистую (`startSession`) |
| Ellipsis-меню (Rename / Delete)     | `/workspace rename <имя> <новое>` · `/workspace delete <имя>`                                                                                                         |
| «+» (New session in …)              | `/workspace <имя>` + `/new`                                                                                                                                           |
| «Add workspace» в шапке раздела     | `/workspace add <путь>` (абсолютный путь; `create` напрямую, как меню)                                                                                                |

Старое имя в `/workspace rename` матчится как самый длинный префикс остатка строки — работают имена
с пробелами. Удаление идёт без диалога-подтверждения (типизированная команда = осознанное действие;
папка и логи сохраняются — семантика та же, что у кнопки). Ошибки/успех показываются короткой
статусной строкой над композером (`.tui-ws-status`), как у `/export-md`.

**Автокомплит имён:** при `/workspace <часть>` — попап с названиями воркспейсов (`↓`/`↑`,
`Enter`/`Tab` — переключение, `Esc` — закрыть; `/workspace ` без аргумента показывает первые 8).
Слова-подкоманды `add/rename/delete` попап подавляют. Тот же capture-паттерн, что у `/session`.

**Кнопки футера сайдбара** (плагин `@linxin666/dsh-remote-web-ui`):

| Кнопка                                                  | Команда-замена |
| ------------------------------------------------------- | -------------- |
| Телефон («Mobile remote control», QR-панель)            | `/phone`       |
| Обновление («Check for updates», панель самообновления) | `/update`      |

Обе открывают свои панели кликом по скрытой кнопке (`clickByLabel`, как `/settings`); закрытие —
штатными кнопками панелей (крестик, клик по маске).

**Доступ телефона по LAN.** dsh слушает только `127.0.0.1:3080`; узкий LAN-сокет `192.168.2.87:3080`
держит `systemd-socket-proxyd` (`dsh-lan-proxy.socket`, см. `dsh.nix`), который пробрасывает на
loopback. Фаервол открывает 3080 только на `net1`. Панель телефона показывает URL
`http://192.168.2.87:3080` — это настройка плагина `publicBaseUrl` в `~/.dsh/settings.yaml`
(`remote-web-ui`); `/api`-фенс принимает этот хост через оверрайд `web-runtime` в профильном патче
(генерируется `dsh-market.nix`; значение `!!js` обязано быть в кавычках — без них YAML читает его
как flow-коллекцию и dsh падает на парсинге оверлея).

CSS:

## Шаг 11 (готово): подсветка JSON в выводе tool calls

Карточки вызова инструментов рендерят вход/выход (IN/OUT) одним текстовым узлом (`.o3BgMG_ioText`
внутри `.o3BgMG_ioCard`). Когда этот текст парсится как JSON (например, вывод `hyprctl -j`,
`sensors -j`, `systemctl -o json`, `nix flake metadata --json`), фича `tui-jsonfmt` перерисовывает
его:

- **pretty-print** — отступы 2 пробела, если JSON был минифицирован
  (`JSON.stringify(parsed, null, 2)`);
- **подсветка синтаксиса** — ключи (светло-стальной), строки (зелёный), числа (золотой),
  `true`/`false`/`null` (лиловый), пунктуация (приглушённый);
- **сворачивание длинных** — вывод > 4000 символов схлопывается до 9 строк, клик по блоку
  разворачивает (состояние запоминается на узел).

Ограничения: не-JSON текст не трогается; вывод > 200 KB пропускается (парсинг на каждый ре-рендер
дёргал бы UI). React переписывает текстовый узел при ре-рендерах, поэтому фича пере-применяется
MutationObserver-ом (тот же паттерн, что `tui-no-tps`).

Классы: `.tui-json`, `.tui-json-{punct,key,str,num,bool,null}`, `.tui-json-collapsed` (CSS в скине).
Это чисто клиентская фича (`client.js`), рестарт dsh не нужен.

## Шаг 12 (готово): кнопка памяти → `/mem`

**Что это.** Плагин **dsh-memento** монтирует в углу экрана плавающую кнопку `#mem-open` («🧠
Memory», bottom-right), которая открывает/закрывает панель наблюдения за памятью (записи, бюджет,
аудит, предложения). В шапке клиента memento упоминается хоткей F9, но в опубликованном клиенте F9
не заведён — единственный реальный триггер панели это кнопка.

**Замена.** Команда **`/mem`** (клиентский источник команд скина, как `/settings`): кликает скрытую
кнопку `#mem-open` (`toggleMemory()` → `document.getElementById("mem-open").click()`). Повторный
`/mem` — и повторный клик — закрывает панель (кнопка — тумблер); внутри панели работают штатные ✕ и
Refresh.

**Почему не `/memory`.** У dsh-memento уже есть host-команда **`/memory`** (управление памятью:
`list`, `add`, `remove`, `consolidate`, `proposals`, `budgets`, `audit`, `export`, `import`). Она
регистрируется в бандле `@deepseek-ai/dsh-web-app`, который грузится раньше скины, поэтому при вводе
`/memory` в меню `/` появляется host-кандидат, а Enter по голому `/memory` уходит в host-claim (ждёт
аргумент), а не открывает панель. Чтобы не плодить дубликат в меню и не ломать управление памятью,
панельная команда называется `/mem` — короткое и терминальное, как остальные команды скина.
`/memory` остаётся за host-командой (полный набор управления), что видно в меню.

CSS:

```css
#mem-open {
  display: none;
}
```

Селектор стабилен: `#mem-open` — постоянный id инжектируемой кнопки. Панель (`#mem-drawer`) не
трогается — открывается по команде, закрывается штатным ✕. Чисто клиентская фича, рестарт dsh не
нужен.

## Важно: русская раскладка → `e.code`

На RU-раскладке `e.key` возвращает кириллицу (физическая `N` = «т»), поэтому **все** хоткеи матчатся
по `e.code` (физическая клавиша, раскладка-независимо). Это касается и шагов 3–4 (исправлены в этой
же правке).

## Локаль: селекторы по `aria-label`

GUI работает в **английской** локали (браузер `en-US`), поэтому все селекторы по `aria-label`
используют английские строки бандла («Send message», «Stop generating», «Branch into a new
conversation», …):

```css
[data-composer-card] button[aria-label="Send message"],
[data-composer-card] button[aria-label="Stop generating"] { … }
```

Если локали в бандле поменяются — обновлять селекторы (ранняя версия шагов 2/4/5 была написана под
zh-CN и в английском GUI молча не работала; потом китайские дубликаты убрали как мёртвый вес).
