# Замена кнопок на команды: план

> Статус: **в работе** — шаги 1–9 реализованы (поле ввода, сообщения, очередь,
> сайдбар, команды сессий, «всегда в конец», авто-разворот правок, шапка/сайдбар
> → `/export` и `/export-md`, удалён чип git-graph, авто-перезагрузка страницы);
> остались кандидаты: кнопки воркспейсов.

## Цель

Постепенно убрать из dsh web GUI кнопки, которые дублируют текстовые команды
(слэш-команды `/…` в поле ввода, хоткеи, Enter и т.п.), чтобы интерфейс был
управляем с клавиатуры, как терминал.

## Принцип

- **Кнопка → команда.** Для каждой кнопки сначала находим (или добавляем)
  текстовую команду/хоткей с той же функцией, затем прячем кнопку.
- **Прячем, а не удаляем.** Кнопки скрываются только CSS (DOM не трогаем) —
  изменение обратимо и не ломает React.
- **Если команды нет — добавляем её**, потом прячем кнопку.
- Место правок — личная скина **dsh-terminal-ui** (форк `dsh-web-ui`,
  `packages/dsh-terminal-ui/lib/client.js`), которая уже владеет внешним видом
  композера и инжектит один `<style>` на время жизни страницы.

## Механика (как вносить изменения)

1. Форк: `~/src/1st-level/@projects/dsh-web-ui` (workspace-link из
   `~/.dsh/profiles/web`, см. `pnpm-workspace.yaml`).
2. Правки — прямо в `packages/dsh-terminal-ui/lib/client.js` (у пакета нет
   `src/`, так уже делались прошлые коммиты `theme(terminal-ui): …`).
3. **Два слоя кода** (частая причина «не работает, хотя сделал»):
   - **клиент** (`lib/client.js`) сервер отдаёт **живьём** из форка
     (проверено: `/plugins/dsh-terminal-ui/client.js` == файл форка; rev-хэш
     пересчитывается на лету). Рестарт не нужен; страница теперь
     **перезагружается сама** (авто-вотчер rev, см. ниже).
   - **host** (`lib/index.js`: команды, роуты, инъекции сервисов) грузится
     один раз при старте dsh — после правок нужен
     `systemctl --user restart dsh`.
4. Проверка клиента: `curl -s http://127.0.0.1:3080/plugins/dsh-terminal-ui/client.js | grep <новый селектор>`.
   Проверка host: `node --check lib/index.js` + рестарт + проверка в палитре `/`.
5. Коммит в форк: `theme(terminal-ui): …` (как в истории).

### Авто-перезагрузка страницы при правках

В `client.js` есть вотчер: раз в 8 с читает свежую boot-страницу (`/`) и
`location.reload()`-ит вкладку, если изменился rev **любого** клиентского
плагина — **или** сервис перезапускался (fetch падал и снова поднялся). Поэтому
правки скина применяются без F5, а после `systemctl --user restart dsh` страница
тоже перезагрузится сама (и в палитре появятся новые host-команды, напр.
`/export-md`). Разбор boot: regex по `window.__DSH_BOOT__ = {...}</script>`.

### Генерируемые конфиги (правило)

`~/.dsh/profiles/web/cordis.patch.yml` **генерируется** из
`modules/user/nix-maid/apps/dsh-market.nix` (активация при rebuild/логине;
в файле шапка «Managed by NixOS — do not edit»). Любые отключения/правки
профиля вносить **в модуль**, иначе при `nh os switch` правка затрётся.
Это же касается отключения плагинов: `- id: <plugin> / disabled: true`
в модуле — и рестарт dsh.

## Шаг 1 (готово): кнопка «+» в поле ввода

**Что это.** Кнопка `+` в левой части поля ввода — это тумблер меню команд
(тот же список, что открывается при наборе `/`). Разметка из
`@deepseek-ai/dsh-client-ui-conversation` (InputBar):

```jsx
<div className="…tools">
  <Tooltip label={t("input.commands")}>
    <button aria-haspopup="listbox" aria-expanded={commandMenuOpen}
            onClick={onToggleCommandMenu}>
      <IconPlusOutline16 size={14} />
    </button>
  </Tooltip>
  …
</div>
```

**Замена.** Функцию дублирует команда `/` в поле ввода — кнопка избыточна.
Скрыта CSS-правилом в `dsh-terminal-ui`:

```css
[data-composer-card] button[aria-haspopup="listbox"] {
  display: none;
}
```

Селектор стабилен: `data-composer-card` — постоянный data-атрибут карточки
ввода; `aria-haspopup="listbox"` в бандле конверсации встречается ровно один
раз. Скролл-зона и клавиатура не затронуты.

**Проверено.** После правки сервер сразу отдаёт обновлённый бандл
(rev `09810766aafd` → `a744c35a19fa`).

## Шаг 2 (готово): Отправить / Стоп

**Что это.** В правой части поля ввода — главная кнопка: «Отправить»
(`aria-label="Send message"`), а во время запуска — «Стоп»
(`aria-label="Stop generating"`, отдельная кнопка при прерываемом запуске
субагента).

**Замена.**
- **Отправить** — уже дублируется **Enter** в поле ввода (Shift+Enter — новая
  строка, Ctrl+Enter — ускоренная отправка/«вставка» в очередь).
- **Стоп** — хоткея не было, добавлен **Esc** (JS-фича в `dsh-terminal-ui`):
  если запуск идёт (кнопка «Стоп» в DOM) и нет открытых попапов/модалок —
  кликаем по ней. Открытые меню Esc закрывает как раньше (React-обработчик
  срабатывает раньше, наш слушатель — в фазе всплытия).

CSS:

```css
[data-composer-card] button[aria-label="Send message"],
[data-composer-card] button[aria-label="Stop generating"] {
  display: none;
}
```

## Шаг 3 (готово): выбор модели

**Что это.** Селектор модели/усилия справа в поле ввода — попап-меню
(`aria-haspopup="menu"`), рендерится в слот `conversation.input.model` внутри
карточки ввода (без портала).

**Замена.** Хоткей **Ctrl+M** открывает пикер (клик по скрытому триггеру),
внутри — стрелки + Enter (нативная навигация меню). Триггер скрыт CSS:

```css
[data-composer-card] button[aria-haspopup="menu"] {
  display: none;
}
```

## Шаг 4 (готово): кнопки на сообщениях и в очереди

**Что это.** Ховер-панель действий сообщения (Копировать / Ветка) и кнопки
очередных сообщений (Изменить / Удалить / Вставка). Хоткеев не было.

**Выбор модели взаимодействия:** хоткеи действуют на **последнее** сообщение
в ленте (решение пользователя) — без трекинга мыши.

**Замена** (модификаторные комбинации — обычные буквы остаются для набора):

| Хоткей | Действие |
|---|---|
| `Ctrl+Alt+C` | скопировать текст последнего сообщения (пользователя или ассистента) |
| `Ctrl+Alt+B` | ветка последнего сообщения (только ассистент, если доступно) |
| `Ctrl+Alt+E` | редактировать последнее очередное сообщение (Enter — сохранить, Esc — отмена) |
| `Ctrl+Alt+Backspace` | удалить последнее очередное сообщение |

Скрыто CSS (копировать/ветка — только внутри `[data-time-hover-root]
[class$="_actions"]`, чтобы не задеть кнопки копирования в блоках кода):

```css
[data-time-hover-root] [class$="_actions"] [aria-label="Copy"],
[data-time-hover-root] [class$="_actions"] [aria-label="Copied"],
[data-time-hover-root] [class$="_actions"] [aria-label="Branch into a new conversation"],
button[aria-label="Edit queued message"],
button[aria-label="Remove queued message"],
button[aria-label="Steer queued message"] {
  display: none;
}
```

Хоткеи диспатчат `.click()` по скрытым кнопкам — работают штатные обработчики
приложения (clipboard, fork, очередь).

## Шаг 5 (готово): сайдбар — новый чат и переключение сессий

**Что это.** Кнопки «New session» в сайдбаре (их две: бренд-слово и подписанная
кнопка с иконкой — обе вызывают `startSession`) и список сессий
(`role="treeitem"` с `aria-selected`; строки папок воркспейсов — с
`aria-expanded`, поэтому не путаются). Хоткеев не было.

**Замена.**

| Хоткей | Действие |
|---|---|
| `/new` (команда в поле ввода) | новый чат |
| `Ctrl+Alt+N` | новый чат (быстрый хоткей) |
| `Ctrl+Alt+J` | следующая сессия в списке сайдбара |
| `Ctrl+Alt+K` | предыдущая сессия |
| `Ctrl+Alt+W` | выбрать рабочую папку (когда поле ввода — триггер «Choose workspace»; Enter в фокусе тоже работает из коробки) |

**Команда `/new` — как это устроено.** Слэш-команды dsh выполняются на хосте
(`ctx.commands.register`), а «новый чат» — клиентское действие, поэтому хостовой
команды мало. Вместо этого скина регистрирует **клиентский источник команд**
(сервис `inputTriggers`, тот же конвейер, что у `/`): кандидат `new` попадает в
меню при наборе `/`, `matchEnter` обрабатывает голый `/new` + Enter, а
`onPick`/`matchEnter` вызывают `ctx.workspaces.startSession()` (то же, что
кнопка) и снимают токен `/new` из поля через событие `slash/input-consume-token`
(как это делает штатный ui-commands). Заголовок отдельной группы меню скрыт CSS
(`[data-source="local"]`), чтобы `/new` читался как часть группы команд.

CSS:

```css
button[aria-label="New session"] {
  display: none;
}
[data-source="local"] {
  display: none;
}
```

## Шаг 6 (готово): переключение сессий командами + всегда в конец

**Команды переключения** (в том же клиентском источнике, что `/new`):

| Команда | Действие |
|---|---|
| `/session <имя>` | перейти к сессии: точное совпадение по названию → префикс → подстрока → фолбэк по содержимому сообщений (`sessions.search`) |
| `/next` | следующая сессия в списке сайдбара |
| `/prev` | предыдущая сессия |
| `/new` | новый чат (как раньше) |

Механика: `onPick`/`matchEnter` источника вызывают `ctx.sessions.open(id)` /
клик по строке списка; токен снимается через `slash/input-consume-token`.
Выбор `/session` из меню оставляет «/session» в поле — дописываете имя и Enter.

**Всегда в конец.** Раньше чат восстанавливал сохранённую позицию скролла при
открытии сессии (оказывались на середине). Теперь скина подписана на
`ctx.sessions.list` (store: `current` — активная сессия): при любом изменении
текущей сессии — клик в сайдбаре, `Ctrl+Alt+J/K`, `/session`, `/next`, `/prev`,
`/new` — скроллпорт `[data-conversation-scroll]` прыгает в конец (двойной rAF +
повтор через 700 мс, чтобы поймать догрузку). Дальше штатный обработчик видит
«внизу» и продолжает следовать за потоком.

## Шаг 7 (готово): правки кода/файлов разворачиваются

Карточки вызовов инструментов монтируются свёрнутыми (тело **не** в DOM, пока
не открыто — CSS не поможет, нужен клик по строке). Авто-разворот (тот же
WeakSet-подход, что у Think/команд/контекста) теперь покрывает и строки
правок: варианты **`edit`**, **`write`**, **`code`** раскрываются сразу;
`read`/`search`/`bash` остаются свёрнутыми, чтобы содержимое файлов не
затопляло колонку. Свёрнутая вручную строка больше не разворачивается (только
новые строки из новых ходов).

### Команда `/export-md`

- **Host** (`lib/index.js`): `inject: ["webServer", "commands"]` +
  `ctx.commands.register({ name: "export-md", description: …, handler: … })`.
- **Клиент** (`lib/client.js`): логика экспорта вынесена из фичи feat-9 в
  общую функцию `exportMarkdown()` на уровне `apply()`; слушатель
  `ctx.on("command/executed", …)` вызывает её при успехе `/export-md`.
  Функция собирает сообщения из DOM (`.Md3f7G_flowItem`: user/assistant
  корни + tool-строки `.Md3f7G_callRow`) и скачивает `.md` через Blob.

  окончательно, код кнопки в feat-9 можно выпилить.

## Шаг 9 (готово): автокомплит имён сессий

Нативное меню `/` дополняет **имена команд**, но не аргументы (триггеры
`/`/`@` работают только по одному токену до пробела). Пока в поле ввода
`/session <часть>` — скина показывает кастомный попап над композером с
подходящими названиями сессий (из `sessions.list` по `displayTitle`, без
id-фолбэков):

- `↓`/`↑` — выбор, `Enter`/`Tab` — открыть сессию (строка снимается через
  `slash/input-consume-token`, как голый `/session`), `Esc` — закрыть, клик —
  открыть.
- Клавиши перехватываются в capture-фазе, чтобы React-обработчик Enter не
  отправил «/session …» сообщением.
- `/session ` без аргумента показывает первые 8 сессий.

## Важно: русская раскладка → `e.code`

На RU-раскладке `e.key` возвращает кириллицу (физическая `N` = «т»), поэтому
**все** хоткеи матчатся по `e.code` (физическая клавиша, раскладка-независимо).
Это касается и шагов 3–4 (исправлены в этой же правке).

## Локаль: селекторы по `aria-label`

GUI работает в **английской** локали (браузер `en-US`), поэтому все селекторы
по `aria-label` используют английские строки бандла («Send message», «Stop
generating», «Branch into a new conversation», …):

```css
[data-composer-card] button[aria-label="Send message"],
[data-composer-card] button[aria-label="Stop generating"] { … }
```

Если локали в бандле поменяются — обновлять селекторы (ранняя версия шагов
2/4/5 была написана под zh-CN и в английском GUI молча не работала; потом
китайские дубликаты убрали как мёртвый вес).
