# DSH web recon — source map for adding "harness features"

## 1. Where the web app source lives; build/serve; the neg fork

- Base (immutable) checkout: `/nix/store/zvfrqpjr7x0w0ns3m53l9sx05wf24scw-dsh-web-en-0.1.0-rc.6/node_modules/@deepseek-ai/` (195 packages). The "web app" is not one package — it is a Cordis host composed from a patch file.
- Key packages: `dsh-web-app` (web surface bundle + `cordis.patch.yml` + `src/startup.ts` CLI), `dsh-base` (shared base `cordis.patch.yml` + host/agent deps), `dsh-web` (web search/fetch capability seam — NOT the server), `dsh-web-frontend` (compiled Vite dist), `dsh-host-webserver`, `dsh-host-apiproxy`, `dsh-client-*` (browser halves), `dsh-agent`/`dsh-agent-loop` (turn driver), `dsh-system-prompt`, `dsh-tools`, `dsh-session*`, `dsh-goal*`, `dsh-tool-todo`, `dsh-compaction*`.
- Build/serve: `dsh --profile web` is parsed by `dsh-web-app/lib/startup.js`. The host serves `dsh-web-frontend/dist` (index.html + `assets/index-*.js`); the dist must be pre-built or boot fails loudly. Server binds 127.0.0.1 (`--host 0.0.0.0` rejected). `dsh-web-app/cordis.patch.yml` overrides `dsh-base` rows and inserts the webserver/api-gateway/workspace/browser-roster rows.
- Runtime profile: `~/.dsh/profiles/web/` (`cordis.yml`, `cordis.patch.yml`, `package.json`, `node_modules`). Plugins are installed there.
- neg fork: `/etc/nixos/packages/dsh/web-ui-en/default.nix` is a `runCommand` that `cp -a` the built `@deepseek-ai` tree, then runs `patch.py` (+ `radii.py`, `codeblocks.py`). `patch.py` is a build-time compiled-bundle string rewriter: Chinese UI copy → English, reasoning blocks → MarkdownText, image-preview scheme fixes. `radii.py` halves border-radius; `codeblocks.py` caps long code blocks with scroll. The output store path is exposed as `dshAiStore` in `/etc/nixos/modules/user/nix-maid/apps/dsh-market.nix`, which symlinks the profile's `node_modules/@deepseek-ai` to it. Fork-plugin source edits hot-apply on refresh; `@deepseek-ai` bundle edits require rebuilding this Nix package + refresh.

## 2. Client plugin format

`package.json`: `"dsh": { "client": { "inject": [...], "platform": "web" } }` (host-side patches optionally add `"bundle": { "patch": "cordis.patch.yml" }`). `exports` has `.` (host) and `./client` (browser). `main` = host ESM entry.

- Host half `lib/index.js`: exports `{ apply, inject }`; `inject` = Cordis service names (`webServer`, `commands`, `tools`, `systemPrompt`, `approval`, ...). `apply(ctx)` registers routes/commands/tools/prompt sections inside `ctx.effect(...)`.
- Client half `lib/client.js`: `window.__ModuleLoader__.load({ id, factory: (require) => { const inject = [...]; function apply(ctx) {...} return { apply, inject }; } })`. `require("react")` works; `ctx.effect` gives disposal; `ctx.slots.inject("tool.call.toolview", function*(){ yield ctx.slots.register({name,key,priority}, Component) })` overrides tool cards; plain DOM listeners + MutationObserver + injected `<style>` are the common pattern.
- Examples: `~/src/1st-level/@projects/dsh-web-ui/packages/dsh-terminal-ui` (host route `/terminal-ui/wallpaper` + `/export-md` command; client theme CSS), `.../dsh-gui-tweaks` (pure client; todo/ask cards via `slots`), `.../dsh-preview` (host-only `/dsh-preview` route). Third-party: `~/.dsh/profiles/web/node_modules/dsh-memento`.

## 3. Chat/session data flow

- Sessions are event-sourced (append-only log). `dsh-session` provides `SessionStore` (ctx key `sessions`); `session.append(type, data, opts)` commits synchronously and notifies `session/event` observers; persistence flushes on `session/flush`. Storage = `dsh-session-persistence-jsonl` → `~/.dsh/sessions/<workspace-slug>/<session-id>/session.jsonl.zstd`.
- The model-visible "surface" is an ordered projection of only `user/message`, `assistant/message`, `tool/result`; `Session.deriveMessages()` builds LLM history. Raw events (turn/step boundaries, `tool/call`, usage, compaction, goal, todo) stay in the log but are not messages.
- Turn driving is `dsh-agent-loop`: an `Agent` machine over an `Inbox` (next-step / next-turn queues). `kick()` loops `turn()`; each step does `systemPrompt.assemble()` → `agent/pre-step` waterfall → `renderPrompt()` → `buildRequest()` → `llm.stream` → tool execution → `step/end`; the turn ends with `turn/end` and the machine goes `idle` (`whenIdle()`).
- Events (full core set in `dsh-session/lib/types/known-event-types.js`): `turn/start`, `turn/end`, `step/start`, `step/end`, `assistant/message`, `tool/call`, `tool/result`, `compaction/*`, `goal/change`, `todo/write`, `session/end-seed`, etc. **There is no `session/idle` or `message/done` core event.** Idle is signaled by `agent/status` (`status === "idle"`) and `agent.whenIdle()`; message completion is `assistant/message` / `turn/end`.
- System prompt: assembled per step in `dsh-agent-loop` (`systemPrompt.assemble(assembleContextFor(agent,signal))`). Contributions registered via `ctx.systemPrompt.section({name, order, text|fn, complete?})`, `ctx.systemPrompt.context(...)`, `ctx.systemPrompt.variable(...)`; a `system-prompt/assemble` waterfall lets plugins mutate the assembly. `dsh-web-app` adds `harness:source` / `app:web-surface` sections; `dsh-agent-instructions` injects the AGENTS.md chain as retained user messages via `agent/pre-step`/inbox, not as a prompt section.
- Tools: `ctx.tools.register(defineTool({ name, description, parameters, output: {schema, render}, execute(args, exec), finalizeContent?, timeoutMs?, isConcurrencySafe? }))`. Built-ins: `dsh-tool-fs` (`read`/`write`/`edit`/`read_image`), `dsh-tool-fs-search` (`glob`/`rg`), `dsh-tool-bash` (`bash`), `dsh-tool-str-replace-editor` (`str_replace_editor`), `dsh-tool-goal`, `dsh-tool-todo`. Pipeline: `tools/pre-execute` (allow/deny; **cannot rewrite args**) → guards → `tools/execute` (around-dispatch wrapper) → `tools/post-execute` (can replace `content` or `value`, attach `additionalContexts`) → `finalizeContent` → observe-only `tools/result`. So results are interceptable; args require wrapping `tools/execute`.

## 4. Todo / goal state; auto-continue

- Todo: `dsh-tool-todo` appends a full-list snapshot `todo/write {todos:[{content,status}]}` to the owning session; current list = most recent `todo/write` event (last-write-wins). It is replay state, not a message.
- Goal: `dsh-goal` (ctx key `goals`) is event-sourced from `goal/change`; one current goal per session; view = `{id, revision, objective, phase, activation (armed/disarmed), roundsStarted, maxGoalRounds, blockedReason}` with CAS mutations. Tools: `get_goal`/`create_goal`/`update_goal`.
- Auto-continue: `dsh-goal-round-driver` (host plane) listens `agent/status` (idle), `agent/inbox/*`, `session/event` (`turn/end`), and `goal/changed`; when armed+active+capacity it flushes, rechecks, then `agent.followup(<goal_round>)`. This is the template for idle continuation.

## 5. Memento (memory tools)

- `dsh-memento` v0.3.1 is a third-party host plugin at `~/.dsh/profiles/web/node_modules/dsh-memento` (entry `index.mjs`, lib/*, client panel). Not in `@deepseek-ai`.
- It implements a tri-role seam: `ctx.provide('memory', service)`; `memory` + `memory_recall` tools via `ctx.tools.register(defineTool(...))`; a frozen system-prompt snapshot via `ctx.systemPrompt.section(...)` (sync, order −50); write approval via `ctx.on('approval/request', answerer)`. Store = SQLite `~/.dsh/dsh-memento/memory.db` (WAL, schema v3; tracks user/agent × scopes user-global/workspace; budgets).
- Session hooks: `ctx.on('session/event', ...)` appends `memory/*` events only if `KNOWN_SESSION_EVENT_TYPES` contains them (rc.6 has no plugin-event registration surface); it listens for `compaction/summary` then `compaction/end` to auto-create memory proposals. Also `/memory` command and `/api/memento/*` web routes.

## 6. Feature integration points

- **(a) Session-idle todo-continuation injection** — server plugin (new fork package, host half). Hook `ctx.on('agent/status', ({agent,status}) => ...)` when `status==='idle'` (or `ctx.on('session/event')` for `turn/end`), scan `agent.session` for the newest `todo/write` event, and if pending/in_progress work remains, `agent.followup(...)` exactly like `dsh-goal-round-driver` (flush + recheck + cancellation pause). Files: `packages/dsh-todo-continue/lib/index.js` + profile `cordis.patch.yml` insert row.
- **(b) rules/*.md injection on read** — server plugin. Best seam is `tools/post-execute` on `read`/`read_document`: on success, walk up from the file's directory collecting `rules/*.md` (mirror `dsh-agent-instructions` AGENTS.md discovery) and attach them as `additionalContexts`. Alternative: a `systemPrompt.context`/`section` rendered per cwd. Do not patch `dsh-tool-fs` itself.
- **(c) Session-end memory extraction** — extend `dsh-memento` (or a plugin with `inject: ['memory','sessions']`). Hook `ctx.on('session/disposed', ...)` for live teardown and/or `session/event` `session/end-seed`/`compaction/end`, then write extracted facts through `ctx.memory.add(...)` (approval-gated). Memento already has the proposal machinery at compaction; session-end adds another trigger. File: `dsh-memento/index.mjs`.
- **(d) Hash-anchored line tags in read/edit** — server plugin. `tools/post-execute` can rewrite `content`/attach context for output tagging; if input anchors must be normalized, wrap `tools/execute` (around-dispatch) because `tools/pre-execute` cannot rewrite args. `read`/`write`/`edit` live in `dsh-tool-fs`.
- **(e) Todo preservation across compaction** — server plugin listening `session/event` for `compaction/end` (or `compaction/summary`), read the current `todo/write` state, and re-inject it as a user-role reminder via `agent.inbox`/`agent.followup`; cheapest is a persistent `systemPrompt.section`/`context` rendering the live todo list so no history is needed. `dsh-compaction-basic` replaces only the derived-history suffix, so durable `todo/write` events survive but their model-visible copies (tool-call args) are shadowed.

Integration-type choice: client plugin = browser UI only; server plugin (host half) = tool/prompt/route/command/event hooks; fork patch (`patch.py`) = compiled `@deepseek-ai` bundle string rewrites only (avoid for logic).
