# Agent-гарды: восстановление из циклов и остановок

Порт из промптов **omp (Oh My Pi)** и **oh-my-opencode (oh-my-openagent)**. Цель: лечить самый
частый реальный отказ агента — «затихание» и петли (повторяющиеся вызовы, повторяющиеся рассуждения,
«сейчас сделаю» без действия), а также резкие смены контекста пользователем.

## Как использовать

Гарды — это короткие инъекции в поток агента, когда харнесс/враппер детектирует условие. Они
вставляются как системное сообщение (пометки `<system-interrupt>` / `<system-injection>` /
`<system-notice>` — агент обязан трактовать их как системные, а не как пользовательский текст).
Порядок: детектор → конкретный гард → агент продолжает с одного конкретного шага.

## 1. Петля вызова инструмента (omp: tool-call-loop-redirect)

Детектор: N одинаковых вызовов одного инструмента с одинаковыми аргументами подряд.

```
<system-interrupt reason="tool_call_loop_detected">
Ты вызвал {{tool_name}} {{count}} раз подряд с одинаковыми аргументами:
{{arguments_summary}}

Последний результат (обрезан): {{result_summary}}

БОЛЬШЕ НЕ вызывай {{tool_name}} с этими аргументами в этом ходе.
Используй другие аргументы, другой инструмент или подведи итог и заверши, если готово.
</system-interrupt>
```

______________________________________________________________________

## 2. Петля рассуждений (omp: thinking-loop-redirect)

Детектор: почти одинаковые рассуждения/ответы повторяются без прогресса.

```
<system-interrupt reason="thinking_loop_detected">
Повторение одного и того же плана/резюме/намерения снова зациклилось. Сломай паттерн:
- ПЕРЕСТАНЬ описывать планируемые действия. Сделай один конкретный tool-вызов — самый маленький реальный следующий шаг.
- Застрял между вариантами → выбери самый скучный рабочий; действуй, не размышляй дальше.
- Задача реально завершена → выдай финальный ответ, а не очередное рассуждение.
Сделай что-то отличное от зацикленного. Действуй, а не перепланируй.
</system-interrupt>
```

## 3. Классификатор неожиданной остановки (omp: unexpected-stop-classifier)

Детектор: сообщение обещает действовать, но заканчивается без действия. Классифицировать одним
словом YES/NO.

**Это неожиданная остановка (YES):**

- «Надо сделать то же для JS-воркера. Делаю сейчас.»
- «Дальше запущу тесты.»
- «Сейчас исправлю это.»
- «Сделать это за тебя?»

**Это не остановка (NO):**

- «Задача выполнена.»
- «Могу ещё чем-то помочь?»
- «Фикс готов, тесты проходят.»

Промпт-классификатор:

```
Классифицируй, является ли это сообщение ассистента неожиданной остановкой: оно говорит,
что будет действовать/продолжать/вызовет инструмент, и заканчивается без этого.

Сообщение:
{{message}}

Ответь одним словом: YES если неожиданная остановка; NO иначе.
```

При YES — вставить гард 4.

## 4. Пустая остановка — продолжить (omp: empty-stop-retry)

```
<system-injection>
Остановка без результата; задача не выполнена. Продолжи: финальный ответ пользователю
или следующий обязательный tool-вызов.
Попытка #{{retryCount}}/{{maxRetries}}
</system-injection>
```

______________________________________________________________________

## 5. Продолжение намерения (omp: auto-continue)

После сворачивания/перезапуска сессии:

```
Возобнови последнее намерение пользователя. Перечитай недавние сообщения выше резюме,
чтобы подтвердить последний запрос. Если он отменяет более ранние планы — следуй ему.
Если работы не осталось — скажи об этом коротко; не выдумывай работу.
```

______________________________________________________________________

## 6. Boulder: невыполненные todo (oh-my-opencode: todo-continuation-enforcer)

Точный текст инъекции из `hooks/todo-continuation-enforcer/constants.ts` (CONTINUATION_PROMPT),
вставляется на событии `session.idle`, когда остались незакрытые задачи:

```
[system-directive todo_continuation]
Incomplete tasks remain in your todo list. Continue working on the next pending task.
- Proceed without asking for permission
- Mark each task complete when finished
- Do not stop until all tasks are done
- If you believe all work is already complete, the system is questioning your completion claim.
  Critically re-examine each todo item from a skeptical perspective, verify the work was actually
  done correctly, and update the todo list accordingly.
```

Механика (для автоматизации): обратный отсчёт 2s (toast 900ms, grace 500ms, abort-окно 3s);
экспоненциальный backoff: база 30s, ×2 за фейл, максимум 5 подряд, затем пауза 5 мин; cooldown 5s;
stagnation-detection (max 3). Не вставлять, когда ждём ответа пользователя
(pending-question-detection) и при свежей компакции (compaction-guard, 60s).

## 7. Прерывание пользователем (omp: user-interjection)

Сообщение пользователя пришло во время работы — приоритет:

```
<system-notice>
Прерывание пользователем во время работы: имеет приоритет; отменяет конфликтующие
предыдущие инструкции. Перечитай и убедись, что текущая работа отражает намерение
пользователя.
</system-notice>
{{message}}
```

______________________________________________________________________

## 8. Эфемерный вопрос по ходу (omp: btw-user)

Пользователь задал короткий побочный вопрос:

```
<btw>
Эфемерный побочный вопрос текущей интерактивной сессии.
Ответь кратко и прямо; используй уже имеющийся контекст разговора.
НИКОГДА не используй инструменты.
НИКОГДА не задавай уточняющих вопросов.
Вопрос: {{question}}
</btw>
```

______________________________________________________________________

## 9. Пользователь раздражён — правило на будущее (omp: omfg-user)

Пользователь жалуется на повторяющееся поведение агента. Вместо обещаний — составить одно конкретное
правило-фильтр (TTSR): regex-условие на потоке вывода/аргументах инструментов + узкий scope +
короткое руководство-коррекция. Условие должно ловить именно оффенсивный вывод из текущего
разговора, а не быть широким «catch-all».

______________________________________________________________________

## Правила внедрения

- Гарды 1–4 и 6 — кандидаты на автоматизацию (хуки/враппер), остальные — по ситуации.
- После любого гарда агент обязан сделать **один конкретный шаг**, а не перепланировать.
- Не вставлять гарды в конфликте с реальным финальным ответом (классификатор №3).
