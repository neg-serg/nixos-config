# Категории намерений вместо имён моделей

Порт из **oh-my-opencode (oh-my-openagent)**. Идея: делегируй по намерению, а не по имени модели.
Имя модели создаёт distributional bias — модель ведёт себя по-разному, когда считает себя «gpt-X»
или «claude-Y»; категория же описывает, ЧТО нужно сделать, а модель выбирает харнесс.

## Категории (из oh-my-openagent)

| Категория            | Для чего                              |
| -------------------- | ------------------------------------- |
| `ultrabrain`         | Сложная логика, архитектурные решения |
| `deep`               | Автономное исследование + исполнение  |
| `quick`              | Одиночные правки файлов, опечатки     |
| `visual-engineering` | Фронтенд, UI/UX, дизайн               |
| `writing`            | Тексты                                |

## Как это уже живёт у нас

Враппер omp (`modules/dev/omp.nix`) делает то же самое через роли:

- `PI_SMOL_MODEL` — реализация после prewalk (аналог `quick`/`deep`);
- `PI_PLAN_MODEL` / `PI_SLOW_MODEL` — планирование и глубокое рассуждение (аналог `ultrabrain`).

## Правило

- В промптах и делегировании называй роль/намерение, а не конкретную модель.
- Модель для роли выбирает харнесс (у нас — враппер omp с DeepSeek-моделями по умолчанию).
- При добавлении новой роли: сначала определи, какое намерение она покрывает, потом — модели.
