# Нишевые фичи omp: порт-заметки (vibe / cleanse / export / secrets / tan)

Пятерка небольших фич omp, которые не тянут на отдельный плагин, но которые стоит зафиксировать как
идеи и заготовки для DSH. Источник: omp 17.3.4 (`/nix/store/.../omp-17.3.4/share/omp/src`).

## 1. vibe — персистентные worker-сессии

`src/vibe/` (runtime.ts, state.ts): «вайб»-режим, в котором директор водит несколько персистентных
агентов-воркеров («CLI»): каждый спавнится один раз (keep-alive), живёт между ходами (TTL park +
JSONL revive), адресуется по имени. Тулы: vibe-spawn/list/send/kill/wait.

**Порт в DSH**: у нас уже есть background-субагенты и `send_message` — это тот же механизм.
Недостаёт только «park/revive» (долгоживущие адресуемые сессии) — можно оформить воркфлоу
«vibe-директор» поверх существующих субагентов, без кода харнесса.

## 2. cleanse — чистка кодовой базы

`src/cleanse/`: команда запускает агентов-дискавери, которые находят чекеры (lint, тесты,
typecheck), затем интерактивно выбирает и прогоняет их, чинит найденное и коммитит.

**Порт в DSH**: воркфлоу в `.agent/workflows/` — «codebase cleanse»: (1) discovery чекеров (just
lint / check / osh -n / statix / deadnix / shellcheck), (2) прогон, (3) починка по фичам, (4)
коммит. По сути уже покрыто `agent-recipes.md` + lint-цепочкой репо; можно собрать отдельный
workflow при желании.

## 3. export — экспорт/шаринг сессий

`src/export/` (share.ts, custom-share.ts, html/, ttsr.ts): экспорт сессии в HTML-страницу для
шаринга, кастомные экспорты, экспорт TTSR-правил.

**Порт в DSH**: у DSH сессии в JSONL и есть Workspace browser; HTML-шаринг — небольшая фича
клиента/команды. Отложить (низкий приоритет).

## 4. secrets — плейсхолдер-сканирование ключей

`src/secrets/` (placeholder-scan.ts, obfuscator.ts, message-transform.ts): детектит в выводе
43-символьные API-ключи (и другие плейсхолдеры), заменяет их на `***`/обфускацию на лету, хранит
per-install ключ в XDG state. Защита от утечки секретов в промпты/логи.

**Порт в DSH**: очень полезно — в DSH-логах и транскриптах могут мелькать ключи. Варианты: (a)
плагин-хук на `tools/result`/`assistant/message` с regex-маскировкой 43-символьных токенов; (b) хотя
бы добавить правило в AGENTS.md: «никогда не выводи токены/ключи целиком, маскируй». Сделать (b)
сразу, (a) — в бэклог.

## 5. tan — смена контекста

`prompts/system/tan-context-switch.md`: быстрый переключатель контекста/проекта, напоминание что
«активный проект — другой, не путай». Идея: явный маркер смены workspace.

**Порт в DSH**: правило в AGENTS.md при работе в нескольких репозиториях: при смене проекта
перечитывать его AGENTS.md и явно фиксировать переключение. Можно добавить одной строкой в секцию
про scope.
