# Budget baseline — 2026-10-23

The first measurement of the whole shell as it actually runs on trantor, taken after the port of the
two side panels (drawers `media` and `network`). It is a **baseline, not a pass**: two of the three
targets below are missed, and that is the point of writing it down.

## Method

- Scene: the session units, five of them, live —
  `pleamar-{bar,panels,notifications,toast,launcher}.service`.
- Memory: `systemctl --user show -p MemoryCurrent` — the cgroup's current usage, the same number the
  module caps (`MemoryHigh` 256M / `MemoryMax` 512M).
- CPU: `CPUUsageNSec` read twice, 45 s apart, on an idle desktop (nothing touched, music stopped) —
  the delta is the cost of simply existing.
- Per-scene samples, frame times and the `--report` of each scene:
  `tests/evidence/2026-10-23-<scene>.{tsv,md,log}` from `scripts/measure.sh`.

## Memory (idle, cgroup current)

| scene                    |        MB | note                                                                                                |
| ------------------------ | --------: | --------------------------------------------------------------------------------------------------- |
| bar                      |      36.3 | the strip, tray, sysmon probe, media capsule                                                        |
| panels                   |      63.0 | **the heaviest**: full-monitor surface + the three plugins (cover, meta, spectrum) + the flow model |
| notifications            |      28.9 | centre and toasts                                                                                   |
| toast                    |      12.0 |                                                                                                     |
| launcher                 |      13.3 |                                                                                                     |
| **total**                | **153.4** |                                                                                                     |
| Quickshell, same session |     217.4 | for scale, not a target                                                                             |

Target **M1: ≤ 60 MB total, hard ceiling 128 MB** — **missed**, by a factor of 2.5. `panels` alone
is over the whole budget.

## Idle CPU (45 s delta, nothing happening)

| scene         | % of one core |
| ------------- | ------------: |
| bar           |          1.88 |
| panels        |          2.49 |
| notifications |          0.41 |
| toast         |          0.35 |
| launcher      |          0.70 |
| **total**     |      **5.83** |

Target **M2: ≤ 1 % idle** — **missed** (Quickshell's baseline was ~4 %, so the port is not yet an
improvement here either).

`panels` is the surprise: it draws nothing when no drawer is open, and still costs 2.5 %. The
surface is always mapped (it has to be, or the scene exits and the drawer cannot be opened from
outside — see the module header), so the cost is in the renderer being asked to produce frames for
an empty overlay at 240 Hz.

## What this means for the gates

- **SC2** (budgets hold for 24 h) — not attempted; a 24 h run needs a session nobody touches, and
  the numbers above already fail, so running it now would only measure a known failure for a day.
- **G3** (budgets) — fails today, with these numbers as the evidence.
- **SC1** (feature parity) — the two side panels are ported; the analyser, the tags and the lock's
  PAM matrix are covered elsewhere.

## Next, in order of effect

1. `panels`: the always-on surface is the suspicious part — measure a build with
   `open: drawer != none` and a socket-activated start, and compare (63 MB and 2.5 % against
   whatever that costs).
1. `bar`: 1.88 % idle for a strip that changes once a minute — the clock tick and the sysmon probe
   (2 s) are the two things to look at first.
1. Only then take a 24 h run, and let it be the gate's evidence rather than a snapshot.
