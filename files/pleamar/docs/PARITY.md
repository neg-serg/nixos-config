# Port status: QuickShell → pleamar

What of the legacy shell in `files/quickshell` has a counterpart in this port, and what has not.
Written because "the capsules are glass" was asked for twice and delivered late: a list makes the
gaps visible before they are asked about again.

**How this was made.** The inventory is the QML tree itself (`Bar/Modules`, `Components`,
`Services`, the top-level areas, and the two big trees `Chaldea/` and `greeter/`). A counterpart is
a scene (`shells/*`), a plugin (`lib/plugins/*`) or a library
(`lib/{capsule,icons,menu,palette}.plm`); evidence is the file headers that name their legacy
(`// Legacy: …`), `docs/INTERFACES.md`, and the behaviour itself. Statuses are by behaviour, not by
line: "ported" means the thing works in the port, not that its QML was translated one-to-one.

**Legend**

|             |                                                                                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ported**  | a counterpart exists and its behaviour is there                                                                                                           |
| **partial** | a counterpart exists with a known gap (named in the note)                                                                                                 |
| **absent**  | nothing in the port                                                                                                                                       |
| **engine**  | the QML object is plumbing the scene language replaces outright (a behaviour, a layout host, a texture helper); there is nothing to port object by object |

### The tray's menu, and where it has to come from

The engine's tray record carries `menu`, but it arrives empty for every item on this host, so the
bar's `tray_menu` surface has nothing to draw and the right button falls back to `tray.context`. The
data is reachable over D-Bus, checked by hand on 2026-10-24:

```
busctl --user call :1.5944 /org/ayatana/NotificationItem/steam/Menu \
    com.canonical.dbusmenu GetLayout iias 0 3 0
→ u(ia{sv}av) 767 0 1 "children-display" s "submenu" 15 (ia{sv}av) 377 1 "label" s "Deadzone Rogue 2 Demo" …
```

Three things this settles. An item's menu is `com.canonical.dbusmenu` at the path its `Menu`
property names (`/org/ayatana/NotificationItem/steam/Menu` for Steam, `/MenuBar` for vicinae). **The
signature differs by implementation**: Steam takes `iias` (the old `parentId` as `i`), the spec's
newer form is `uias`, so a client tries both. And vicinae's `/MenuBar` is not dbusmenu at all — it
answers "No such method `GetLayout`" — so its own icon can only be activated, not drawn.

That is work for a plugin (`lib/plugins/traymenu`), not for the scene: the scene can draw rows, but
a plugin is what runs `busctl`, parses the layout and hands the labels over as texts. Activation is
`com.canonical.dbusmenu.Event(id, "clicked", variant, timestamp)`.

## The short version

Ported, in the sense that the thing works: the bar and all its capsules, the launcher, notifications
(cards), overlay, overview, the drawer pages, the plugins (cover, meta, mpd, pill, spectrum,
genelec), the palette and its scripts, and the login/lock card.

Absent outright: the tray menu's submenu search field (`SubmenuHost`, `MenuUtils`), the number-roll
animations, and Chaldea's 295 art files.

Partial, with the gap named above: the tray's hold/collapse state machine, connectivity/VPN, weather
values (no network on this host), notifications history, the greeter's theme variants, and the
helper set.

### What is actually complete

Bar capsules and their geometry (clock, workspaces, keyboard, network, sysmon, media, volume, mic,
genelec, weather), the drawer pages, the notification server with history and DND, the toasts, the
screenshot card, the lock card and its PAM check, the overview scene, the plugins (cover, meta, mpd,
pill, spectrum, genelec), the palette pipeline and the theme scripts, the launcher (which the
reference does not have at all), and the six services pleamar itself provides (clock, audio,
network, media, workspaces/window, tray list, notifications).

### The order the gaps fight each other in

1. The tray: nothing paints, and it is the one thing on the bar that looks broken rather than
   unfinished.
1. Tooltips: every capsule in the reference explains itself on hover; the port has a surface that
   cannot show.
1. The dead clicks (clock, weather, workspaces, sysmon, keyboard, volume): six affordances that do
   nothing is worse than six that are absent.
1. The pill: it is the only reminder the shell has.
1. The overlay host, then the calendar and the notification centre keyboard navigation — the two
   drawers a keyboard user cannot work.
1. Everything else in the tables above, with the settings surface folded into whichever widget is
   being ported.
